Checked 8 October 2026 · Research update 029

ShotStream reaches near-playback speed on an H200. Its released example still saves a file.

Paper reports: 15.95 generated FPS at 832×480 on one H200 for a multi-shot story model. The public command reads prepared prompts and writes a final MP4; live control and viewer delivery are unmeasured. Read the client boundary.

What works today

ShotStream multi-shot research route: paper-reported 15.95 generated FPS on one H200 at 832×480, but the released example is CSV-to-final-MP4. Test a real prompt change and viewer receiver before calling it an interactive service. Check the evidence.

Veda H3 ComfyUI: a project-reported 5070 sparse-attention route for shorter offline clips, not a live stream. Compare the full 130.1-second job and accepted audio/video before changing a workflow. See the timed setup.

RAVEN ComfyUI preview: incremental H3 T2VA browser media is implemented, but the cited 24-GiB envelope was simulated on an H200 and the long test used synthetic conditioning. The maintainer advises 160 GiB available host RAM; physical 24-GiB full-prompt fit is untested. Check the hardware and prompt split.

Full-duplex preview, not a setup recommendation: Tavus Griffin-Lite has a reported streaming video-to-video conversation route, but no customer access or Griffin-specific price. Its component and benchmark timing must not be read as one end-to-end wait.

New offline control route: H3 mask editing is merged in vLLM-Omni’s video API, while its dedicated ComfyUI client remains open. It returns a completed edited video; do not treat it as mid-session control or borrow FastH3 timing from a different task.

New Hopper lead: the eight-H100 saved-MP4 result beats the clip playback clock, but it does not measure a repeated stream. The project has not completed its quality suite. Compare it only with the exact checkpoint, output and warm state pinned.

New route: TaoMate-H3 documents chunked T2AV on eight H20s. Its first-playable benchmark is not a receiver-visible stream; a 5090 LoRA adaptation is a separate offline route. Sol-H3 makes H3 clips faster than their nominal playback duration on eight B300s in a warm partial-pipeline benchmark. It does not yet add a measured live system. The four-step adapter, hardware count and excluded encoding matter more than the headline multiplier.

S2-Editing is a source-fed visual effect, not a text-to-video story engine. Its documented live transport does not establish viewer-visible delay or reliable long sessions. The recent H3 short-clip timing is a complete-response result, not a live session. The prior longer FastH3 profile returned a different clip before playback ended. Keep their durations and setup conditions separate. Read the long-video boundary.

The pre-download card

For a frame-carried loop, record readiness first, then the model and adapter, GPU count, frame grid, conditioning asset, and visible handoff. Only after that should you compare warm time, quality, price, queue margin, or audience wait. A carried last frame is not a promise that the next shot holds together.

Choose the required behavior

  • I need to edit a finished H3 clip: the vLLM-Omni API accepts source media and masks; check its exact server and client revisions before choosing ComfyUI. A completed edit is not live control.
  • I need to alter a camera feed during a live session: inspect Vidu S2-Editing’s RTC input and RTMP relay path; budget its per-live-second charge and measure the change at a viewer receiver.
  • I need a longer completed H3 clip: the v0.30.0 Ref2VA continuation route is a lead. Test the full wait, audio/video join, memory, and usable-output cost before treating the 300-second request guard as usable duration.
  • I need a first/last-frame H3 transition through vLLM-Omni: inspect the current client scope before choosing hardware. The server recipe can express both frames; the current ComfyUI client cannot send both.
  • I need a frame-carried FastH3 editing loop: inspect Dreamverse’s four-GPU Preview v1 profile, then measure readiness, handoff, and the viewer-visible result before promising continuity.
  • I need an offline H3 test on two RTX 5090s: the documented DLO launch selects FL2VA, which also serves T2VA. Budget for a 384 GiB host and an eight-minute returned artifact, then test your required task separately.
  • I need a fast complete H3 response: inspect vLLM-Omni’s eight-B300 FastH3 T2VA result, then verify cold start, queue, playable media, and first visible frame before you promise live video.
  • I want the crowd to choose the next scene: study YoLive’s collective control loop, then ask for a timestamped vote-to-screen record.
  • I want viewers to alter a held stream: compare Director’s session behavior with the interaction delay and restart plan you can afford.
  • I want a local continuous feed of distinct scenes: investigate the one-5090 FastH3 route as a named workflow, then test its motion, quality, queue, and long-run cost.
